5. ALERT TYPES
--------------------------------------------------------------------------------
1. Blood Availability Alert:
   - Patient monitors specific blood group (A+, A-, B+, B-, AB+, AB-, O+, O-) near a city/location radius (5KM - 50KM).
   - Subject: 🩸 [Group] Blood Availability Alert – HealthVerse
2. ICU Bed Availability Alert:
   - Patient gets notified when ICU beds transition 0 -> 1+ at a nearby hospital.
   - Subject: 🚨 ICU Bed Availability Alert – HealthVerse
3. Hospital Admin Low-Resource Threshold Warning:
   - Hospital Admin configures ICU/resource thresholds. When resources fall to or below threshold, alert triggers.
   - Subject: ⚠️ Low ICU Availability – HealthVerse
4. Hospital Approval Notification:
   - Sent to Hospital Admin when Super Admin approves hospital registration.
   - Subject: ✅ Your Hospital Has Been Approved – HealthVerse

6. NOTIFICATION LOGIC & SPAM PREVENTION
--------------------------------------------------------------------------------
- Location Matching: Uses Haversine distance formula between hospital coordinates and alert location. Only triggers if distance <= radius_km.
- Duplicate Prevention: Evaluates last_triggered_at (minimum 1-hour cooldown between duplicate alerts for the same condition).
- State Transition Checks: ICU alerts fire only on 0 -> 1+ transitions. Threshold warnings fire only when resource drops below configured cutoff.
- Non-Blocking Execution: If server-side email dispatch fails or API key is unconfigured in development mode, the error is recorded in email_notifications as failed/simulated without crashing the application or rolling back resource updates.

7. SECURITY
--------------------------------------------------------------------------------
- Zero Secret Exposure: RESEND_API_KEY is NEVER exposed in Vite/React frontend client bundles.
- Server-Side Dispatching: Email dispatch logic executes strictly via backend endpoint /alerts/send-email or server handler.
- Access Control: Email History & Alerts are scoped to authenticated users.
